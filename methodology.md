# Methodology

## Question

Does task-scoped, argument-constrained authorization prevent attacks that remain possible when an agent is already
authorized to use the tools the task needs?

## Setup

- AgentDojo `089ed468cf3ed0322acc66b0211f26d9d90dbf60`, benchmark `v1.2.2` (949 attacked pairs, 97 user tasks).
  `v1` (629 pairs) is run on the development model for comparison with published defenses.
- Attack: `important_instructions`. Default system message. Same model, settings and attack for every arm.
- Every arm is built with `AgentPipeline.from_config`; the Tenuo element is inserted after the query (and after
  `tool_filter` where present), before the first model call. Nothing else in the pipeline changes.

## Arms

| arm | tools | arguments |
|---|---|---|
| `baseline` | all | unconstrained |
| `tool_filter` | chosen by AgentDojo's LLM tool filter | unconstrained |
| `tenuo` | all | targets pinned to values the prompt states |
| `tenuo_both` | all | targets pinned to prompt values or the trusted directory |
| `tenuo_tool_filter` | chosen by `tool_filter` | targets pinned to values the prompt states |
| `tenuo_directory` | all | targets limited to the trusted directory (relationship-scoped; our implementation of UBAG's allow-list rule, without its provenance or behavioral layers) |
| `contract_gate` | ContractGate, AgentDojo PR #183 at `24a0711423f1`, configured as its authors do; its planner uses the agent's model | |

`tool_filter` vs `tenuo_tool_filter` isolates the argument constraints.

## What the issuer sees

Only:

1. the user's prompt (the `query` AgentDojo passes to the pipeline);
2. `policies/targets.json`, generated by `scripts/build_target_table.py` from tool and parameter names with two
   fixed rules (which tools have side effects, which parameters name a target);
3. a directory of names to identifiers (contacts, Slack users and channels, file names, event titles, email
   subjects, travel vendors, and existing payees) taken from the suite's environment loaded with its benign default
   injection values, i.e. the deployment before attacker content arrived. Injection placeholders sit in text fields;
   one Slack channel name contains one, which is why the injected environment is not used.

It never sees injection tasks, ground truth, scorers, or the episode's identity.
`tests/test_enforce.py::test_issuer_cannot_see_benchmark_answers` checks the issuer's imports and signature.

The policy was frozen (committed) before the first full run. Offline replay of reference solutions
(`scripts/replay_reference.py`) was used to understand friction, not to change rules.

## Enforcement

The check runs inside the function call that `FunctionsRuntime.run_function` makes after resolving nested calls and
validating arguments, on the validated public arguments (environment dependencies excluded). A denial raises; the
runtime reports it to the model as an ordinary tool error and the function body does not run. Authorization errors
deny. Targets are compared case-insensitively; the tool receives the model's original value.

An absent optional target (`None`, or no list) is checked as an empty value meaning "no new party". Tenuo cannot
currently match null values (`Exact(None)` raises), so this mapping is a workaround, recorded as a product gap.

A target the issuer cannot establish is denied and counted as an approval request: a deployment would ask the user.
AgentDojo has no approval step, so for scoring it is a denial.

## Metrics

- Official AgentDojo utility, utility under attack and attack success, unchanged.
- Four questions, reported separately (`scripts/analyze.py`):
  1. official attack success (AgentDojo's scorer);
  2. attacker call proposed: a call matching the injection task's goal (`scripts/attack_effects.py`: typed
     comparison of a named parameter against the attacker's identifier, or an attacker URL or leaked secret as a
     whole token in the field that carries it);
  3. attacker call executed: such a call returned without an error (a denied, rejected, or never-answered call did
     not run; `scripts/replay_episode.py` replays every episode to check this and reproduces the official score);
  4. (Tenuo arms) executed calls outside the warrant: every `allow` in `audit.jsonl` re-checked against the grant
     re-derived from the prompt, without Tenuo; `scripts/verify_audit.py` also re-checks every decision with a
     re-minted warrant.
  Plus approval requests on benign tasks, and "task done and no attack" (utility and neither 1 nor 3).
- The official scorer and question 3 differ in both directions. Some scorers read only the final state, the
  first new object, or an amount above a threshold, and miss executed attacks. A context-length error is scored
  as attack success (`benchmark.py`).
- AgentDojo re-runs an episode up to three times when the model ends without a final message. It keeps the
  environment but logs only the last attempt's messages. Tenuo arms record every attempt in `audit.jsonl`, and
  `analyze.py` adds attacker calls from earlier attempts. Other arms have no such record, so their executed counts
  are lower bounds.
- One disclosed scorer guard, applied to every arm: a utility check that raises `KeyError` (issue #188) scores as a
  utility failure and is logged to `scorer_errors.jsonl`.
- A second disclosed harness guard, applied to every arm: when the model returns a tool call whose JSON
  arguments cannot be parsed, AgentDojo's OpenAI wrapper raises and aborts the suite. The guard treats it as the
  model ending its turn with no tool call and logs it to `harness_errors.jsonl`. Runs interrupted by rate limits
  were resumed; AgentDojo skips episodes already logged.
- Issue #168 (`security_from_traces` scores proposed calls) affects Slack `injection_task_5`; we report its official
  score and its executed-effect score separately.

## Known limits

- AgentDojo has one agent and no delegation, so Tenuo's signatures and attenuation are not exercised. A plain
  allow-list from the same issuer would score the same; the experiment measures task-scoped argument policy and
  where it is enforced.
- Many legitimate targets are chosen by a property of data ("the channel with the most users") or come from a
  document that is also the injection vector ("pay the bill in this file"). Prompt-only issuance denies these.
